# Go house 規約

一般的な Go 作法は書かない。**house の選択**と**事故になる罠**のみ。

## 構造は repo から導出する

**この規約は層構造を指定しない**。`internal/` か `controller/pkg/` か は repo が決める。作業前に既存の配置を読み、それに従う。

layout に依らず守るもの: `util` / `common` / `helper` の catch-all package を作らない。entry point に business logic を置かない。

## acronym は全大文字保持

`revive` の initialism リストに 2 文字 acronym が無く lint で落ちないため、house 独自ルールとして持つ。

| 対象 | 正 | 誤 |
|---|---|---|
| 3 文字以上 | `URL` `ID` `HTTP` `API` | `Url` `Id` `Http` |
| 2 文字 | `AI` `IO` `UI` `OS` `DB` | `Ai` `Io` `Ui` |
| 商標 | `OpenAI` `OpenAPI` `gRPC` | — |
| 商標が unexported の先頭 | `openaiKey` `openapiSpec` | `openAIKey` |

最下行に注意 — 商標が先頭に来る unexported 識別子は**商標部分も lowercase** 化する。

## error

- sentinel error は `var Err... = errors.New("pkg: human message")`。message の **`package:` prefix** で wrap chain を読みやすくする
- **upstream SDK の error を handler / gRPC response に leak させない**。外向き message と内部 wrap chain を分離し、詳細は logger 側へ

## log

- `log/slog` + 構造化 JSON
- **log message は固定文字列、可変値は attr**。`slog.Info(fmt.Sprintf(...))` は禁止 (cardinality と grep 容易性)
- PII / 認証情報を出さない

## コメント

- **WHY を書く。WHAT は code が語る**
- **Phase / ticket ID を残さない** (`Phase 0` 等の時系列・ticket scope 言及)
- 直下 code の逐語訳 doc block を書かない。**隣接 code がそうなっていても真似しない** — 過去の生成物が規約から drift している可能性がある

## その他の house 選択

- magic number / 繰り返す literal (文字列 key・閾値・timeout・URL path) は named const へ抽出。関連定数は 1 つの const block に
- exported / unexported は**今公開する必要があるか**だけで決める。「将来公開するかも」は unexported
- **理由コメントの無い `// nolint:` を書かない** — 正: `// nolint:errcheck // intentional fire-and-forget`
- `golangci-lint` は v2 系

## 違反に見えても違反でないもの

生成コード (`Code generated by ... DO NOT EDIT.`) / library の固定 signature / code・docs に意図が明示された例外 / 後方互換のため変えられない exported symbol。**疑わしい場合に勝手に除外せず、flag して user 判断を仰ぐ**。
