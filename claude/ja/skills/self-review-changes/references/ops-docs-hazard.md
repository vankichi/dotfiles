# ops-docs-hazard — 運用手順 docs の危険性

skip 可: runbook / 障害対応 / CLI 手順の docs diff が 0 (`docs/runbook/**` 配下の変更が無く、かつ docs の追加行に shell command の code fence が無い)。

**読み方**: 「文章として正しいか」ではなく「**この手順を文字通り実行した運用者が誤った / 破壊的な行動を取らないか**」で読む。code lens 系観点 (correctness / test-adversarial 等) は code diff 0 で skip されるため、docs 専用変更ではこの観点が唯一の防波堤になる。

- **影響 scope の明記**: 記載した各 command が **単一対象 / 全件 / 不可逆** のどれかを本文で判別できるか (例: 全件を対象に動く command を「1 件だけ処理する手順」の文脈に置いていないか)。scope の明記が無い command は**致命的**扱い
- **破壊的 command の扱い**: 不可逆 command (全件破棄 / 削除 / 強制上書き) は明示禁止か、guard (事前確認・条件・承認) 付きか。同一 file 内の別節の記述から不可逆 command へ読み手が辿り着く経路 (「削除するには」に手段が無く別節の破壊的 command が唯一の候補になる等) が生まれていないか
- **前提の充足性**: 手順の前提 (必要権限 / 可視性・時間の窓 / 実行順序 / 事前状態) が手順内で満たせるか。前提を満たす step が別 doc にしか無い場合は link があるか
- **行き止まりの有無**: 提示した代替手段・次の step が**実在するか** (存在しない command / 未実装の機能 / 権限が無い操作を「こうする」と書いていないか)
- **禁止・警告の実効性**: 禁止事項 / 警告の対象が、実際にその挙動を決める knob を指しているか (実効値を決めない側の設定を禁止しても効果が無く、同節内で自己矛盾する)
- **再課金 / 副作用のコスト**: 手順の再実行が外部 API の再課金や重複処理を招く場合、その旨と回避条件が書かれているか
- **量化子の反例経路**: 「唯一 / 常に / 必ず / のみ / 無条件」等の全称表現ごとに反例経路を 1 つ探す。成立経路の列挙を伴わない量化子は指摘対象 (`~/.claude/rules/verify-before-assert.md` の量化子行)
